# 驰援答辩要点

## 设计决策

1. **为什么前端只读 bridge 产物、不重训模型？** 模型训练与调度计算分离，演示稳定、可复现；实时重训会增加耗时和随机性。
2. **为什么 LLM 不进 A* 内层？** 状态扩展调用 LLM 会放大延迟和不确定性；LLM 只把结构化指标转成解释。
3. **为什么用 `scenario_hash + group` 绑定结果？** hash 锁定场景和调度参数，group 锁定计算组别，避免误用旧结果。
4. **为什么两级输入？** 用户可能已有 demand/risk，也可能只有村庄/道路特征。最小输入直接调度；完整输入先预测再允许覆盖。
5. **为什么 `input_mode` 不进 hash？** 它只表示数据来源，不改变调度输入；相同最终 demand/risk 不应产生新场景。
6. **为什么缺失特征拒绝预测而不是补默认值？** 编造特征会生成不可解释、不可复现的预测；逐行拒绝能保留其余合法行并明确错误。
7. **为什么最终 demand/risk 才进 hash？** A* 直接消费最终值和路网参数；原始特征只是预测依据，不直接决定路径。
8. **为什么 base_speed 兜底要显式标记并纳入 hash？** 50.0 会实际参与调度，不记录会误导用户；显式 50 与兜底 50 也必须区分。
9. **为什么用户单方案不和示例 A/B/C 混排？** 用户只有一套配置，示例 A/B/C 是参考实验；分区展示避免数字被误读。
10. **为什么实时计算区分有旧结果与从未成功？** 前者可保留连续界面，后者没有可信结果，不能用示例代替用户结果。
11. **为什么持久化场景损坏时切回示例？** 演示工具必须可启动；校验失败后恢复示例并给出中性提示，不阻塞页面。

## 已知局限

1. **单用户持久化**：`active_scenario.json` 未做多用户隔离。
2. **示意路网**：不是真实 GIS，不追求地理精度。
3. **单方案对比**：用户场景不运行 A/B/C。
4. **what-if 不自动重算**：AI 只做规则推演，不自动重跑 A*。
5. **base_speed 兜底**：未填写时使用 50.0，虽已标记并进入 hash，但仍不是用户真实值。
6. **范围保护非统计置信区间**：模型输入边界用于业务校验，不代表模型置信范围。
7. **外部 LLM 验证有限**：成功路径主要基于模拟响应，无 Key 和失败回退已覆盖。
8. **前端部署**：Next.js 静态页面通过 FastAPI 单入口读取调度结果，Vercel 构建不依赖在线地图。
9. **失败现场呈现**：已保留上一次有效结果的分支由测试覆盖，现场使用预录片段，不增加隐藏开关。
