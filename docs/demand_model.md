# 需求预测模型说明

## 1. 目标与数据版本

本阶段目标是选择一个适合后续 `bridge.py` 加载的需求预测模型，不包含风险评估、调度器或前端集成。

当前训练数据为加入非线性结构后的 `data/synthetic/demand.csv`，共 498 行，MD5 为 `d72630b26581f88a25e97b68aec6f4af`。本文指标均基于该版本数据。

## 2. 特征与标签

| 特征 | 说明 |
|---|---|
| `population` | 村庄人口 |
| `disaster_level` | 灾情等级 1~5 |
| `distance_to_center` | 到指挥中心距离 |
| `road_accessibility` | 道路可达性 0~1 |
| `weather_code` | 天气有序编码 |
| `is_priority` | 是否优先村 |
| `hist_demand_mean` | 截至前一天的 7 天真实需求均值 |

标签：`demand`。

天气采用有序编码：`晴 = 0`、`雨 = 1`、`暴风 = 2`。三种天气的严重程度单调递增，数据生成公式也使用单调乘数；在当前样本量下，有序编码比 one-hot 更紧凑，并保留顺序信息。

## 3. 时间切分

先按 `date` 升序排序，再取前 70% 日期训练、后 30% 日期测试，不使用随机切分或 shuffle。

| 项目 | 训练集 | 测试集 |
|---|---:|---:|
| 日期数 | 58 天 | 25 天 |
| 行数 | 348 行（69.88%） | 150 行（30.12%） |
| 日期范围 | 2025-06-08 ~ 2025-08-04 | 2025-08-05 ~ 2025-08-29 |
| 村庄覆盖 | 1~6 全部 | 1~6 全部 |

程序会检查训练和测试日期不重叠，并验证两边均覆盖全部 6 个村庄。

## 4. 候选模型与超参数

| 候选 | 说明 |
|---|---|
| `history_mean` | 直接把测试集的 7 天历史均值作为预测值 |
| `linear_regression` | 普通线性回归 |
| `rf_default` | 默认随机森林，`max_depth=None`、`min_samples_leaf=1` |
| `rf_tuned` | 调参随机森林，`max_depth=6`、`min_samples_leaf=5` |
| `linear_regression_log1p` | 线性回归，训练 `log1p(demand)`，预测后 `expm1` 还原 |

公共配置：`n_estimators=300`、`max_features=1.0`、`random_state=42`、`n_jobs=1`。`n_jobs=1` 是因为当前 Windows 沙箱无法创建 joblib 多进程线程池；数据量较小，单线程没有明显性能问题。

本阶段没有进行网格搜索，只比较指定的默认 RF、单一调参 RF 以及一次 log1p 尝试。RF 的 `log1p` 实验也执行了，但未达到保留阈值，详见下一节。

## 5. 测试集结果

| 模型 | MAE | RMSE | R² |
|---|---:|---:|---:|
| 历史均值 | 23.8276 | 35.0819 | 0.9213 |
| 线性回归 | 21.1385 | 29.1418 | 0.9457 |
| RF 默认 | 21.1450 | 29.8149 | 0.9432 |
| **RF 调参** | **18.8501** | **27.1728** | **0.9528** |
| 线性回归 + log1p | 19.0180 | 28.4664 | 0.9482 |

log1p 试验结果：

- LR + log1p 的 MAE 相对普通 LR 降低 **10.03%**，超过 3% 阈值，因此保留在对比结果中。
- RF 调参 + log1p 的 MAE 为 `19.3283`，相对普通调参 RF 反而变差 **2.54%**，因此放弃，不写入 `demand_eval.csv`。

## 6. 最终选型

**最终部署模型：RF 调参（`max_depth=6`、`min_samples_leaf=5`）。**

选型理由：

- 在时间外推测试集上，RF 调参的 MAE `18.8501` 为所有候选最低。
- 相比普通线性回归，MAE 改善 **10.83%**，RMSE 改善 **6.76%**，R² 从 `0.9457` 提升到 `0.9528`。
- 相比 LR + log1p，RF 调参仍有更低的 MAE（`18.8501` vs `19.0180`）。
- 加入阈值效应和灾情 × 可达性交互后，数据不再近似纯线性；RF 的树分裂能够表达灾情阈值和交互，调参后又抑制了过拟合。

该结论只适用于当前模拟数据集和当前时间切分，不应外推为“RF 在所有需求预测任务中都优于 LR”。

## 7. 过拟合缓解

| 模型 | 训练 MAE | 测试 MAE | 差距 |
|---|---:|---:|---:|
| RF 默认 | 9.2518 | 21.1450 | 11.8932 |
| RF 调参 | 18.5839 | 18.8501 | **0.2661** |

调参把训练/测试 MAE 差距从 `11.8932` 降到 `0.2661`，过拟合明显缓解。默认 RF 训练误差很低但测试误差高；限制深度并增大叶节点样本数后，训练误差上升，但泛化显著改善。

## 8. 特征重要性

调参 RF 的 Top 3 特征：

| 特征 | 重要性 |
|---|---:|
| `hist_demand_mean` | 0.3221 |
| `disaster_level` | 0.1457 |
| `distance_to_center` | 0.1446 |

历史需求均值仍是首要信号；灾情等级和距离的重要性接近，说明阈值效应和空间难度都参与了预测。特征重要性只描述当前模型在当前数据上的分裂贡献，不代表因果效应。

## 9. 最大测试误差

- 村庄：6
- 日期：2025-08-14
- 实际需求：389 箱
- 预测需求：303.17 箱
- 绝对误差：85.83 箱

当天为晴天，`hist_demand_mean` 为 `316.57`。实际需求比历史均值高约 23%，属于高需求正向波动；调参后的 RF 更平滑，没有外推到该局部高点，因此出现明显低估。村庄 6 本身是高需求、高方差村庄，这类极端日仍是主要误差来源。

## 10. 相对历史均值的实际增益

最终 RF 调参模型相对历史均值基线：

- MAE 从 `23.8276` 降到 `18.8501`，降低 **20.89%**。
- RMSE 从 `35.0819` 降到 `27.1728`，降低 **22.54%**。

## 11. 持久化产物

| 文件 | 内容 |
|---|---|
| `models/demand_model.pkl` | 最终部署模型，当前为调参 RF |
| `models/demand_rf.pkl` | 调参 RF 对照模型 |
| `models/demand_model_meta.json` | 模型类型、特征顺序、训练/测试日期、指标、数据 MD5 等 |
| `outputs/demand_eval.csv` | 5 个保留候选的 MAE、RMSE、R² |
| `outputs/demand_pred_vs_actual.png` | 最终模型测试集预测 vs 实际 |
| `outputs/demand_feature_importance.png` | 调参 RF 特征重要性 |
| `outputs/demand_model_compare.png` | 候选模型指标对比 |

部署模型直接保存为 sklearn 估计器，`bridge.py` 可按 metadata 中的 `feature_order` 组装特征后调用 `.predict()`。当前 `target_transform` 为 `none`，不需要额外逆变换。

## 12. 连续交互验证

全样本 OLS 补验中，`interaction = (disaster_level - 1) / 4 * (1 - road_accessibility)` 的系数为 **447.58**，p=`0.0118`，显著为正，说明灾情与低可达性的交互效应确实进入数据。它也是调参 RF 能获得优势的数据基础之一。

## 13. 还需要注意

- 测试期天气类型覆盖有限，暴风样本可能不足，不能据此判断暴风对模型贡献很小。
- 高需求村庄的极端波动仍是最大误差来源；如果后续调度对峰值更敏感，可讨论分位数损失或专门的高需求模型。
- 当前未做统计显著性检验来比较 RF 与 LR 的测试误差差异，本文的“最优”指测试集 MAE 点估计最低。
